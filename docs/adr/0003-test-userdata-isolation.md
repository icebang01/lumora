# ADR-0003：测试启动必须用独立 user-data-dir

- 状态：已接受（2026-08，冒烟测试假失败排障后确立）

## 背景

排查"测试打印头后 ~3.5 秒 exit 0、渲染端零输出、无 crash 事件"时发现：**用户正开着的播放器实例锁定了默认 Chromium profile**（GPU cache "access denied"）→ 测试实例渲染进程起不来 → 浏览器进程干净退出 code 0，无任何 JS 报错。若共享默认 profile，任何自动化测试在用户使用播放器时都会假失败，且症状极易误判为业务代码回归。

## 决策

- 所有测试启动器（`tools/run-smoke.js`、`tools/run-gui-test.js`）**自动追加独立 `--user-data-dir`** 并跑完清理。
- 用户实例与测试实例并行共存，互不干扰。

## 权衡

- 代价：测试环境与真实 profile 隔离（不读用户配置/续播数据）——测试本就应自包含。
- 收益：用户开着播放器时测试照跑；排障时间从小时级降到零。

## 后果

- 新增测试启动器必须内置隔离 userData，否则视为缺陷。
- CI 中同样有效（无头/有头 runner 均不依赖默认 profile）。
